# 流式视频 Prompt 改写

把一句简短的想法（或一组有序的事件想法）改写成详细、客观、单段落的视频 prompt，让流式视频模型可以无限延展下去，而不会走进死胡同。

## 文件

- `system_prompt_CN.md`：完整规则（中文）。每次会话第一次改写前先读一遍。它也可以直接当 system prompt 使用，取 `BASE` 段落再加一个 `MODE` 段落即可。
- `examples_CN.md`：各模式的完整示例和常见转换速查（中文）。它是按中文单独写的，不是 `examples.md` 的逐条翻译：示例内容和节号都不同，还多了一个“主体静止时仍要有可见动作”的单事件示例。
- `SKILL.md` / `system_prompt.md` / `examples.md`：同一套规则的英文版，输出英文 prompt 时读它们。
- `scripts/validate_prompt.py`：规则校验器和流水线辅助函数，中英共用一份，仅依赖 Python 3 标准库。违例信息的语言用 `--lang` / `lang=` 选择，检查项本身与语言无关。

## 选择模式

| 模式 | 输入 | 输出 |
|---|---|---|
| 单事件 | 一句话 | 一条 prompt |
| 批量多事件 | 事先全部已知的 N 个有序事件 | N 条 prompt，用只含 `@@@EVENT_BREAK@@@` 的行分隔 |
| 逐事件流式 | 已定稿的历史改写 + 一个新的原始事件 | 只输出新事件的一条 prompt |

事件以交互方式到达时（上一个事件生成完才写下一个），用逐事件流式模式，它不会看到未来的事件。只有整个序列事先已知、可以提前统筹一致性时，才用批量模式。

## 硬性规则

1. **只能用静止或跟随镜头。** 恰好选择一种基础行为，并用标准句原样陈述一次：
   - 静止：中文 `镜头保持静止，始终将<主体>保持在画面中央。`，英文 `The camera remains static, keeping <named subject> centered.`
   - 跟随：中文 `镜头跟随<主体>移动，始终将<主体>保持在画面中央。`，英文 `The camera tracks <named subject>, continuously keeping <named subject> centered.`

   明确的主体在空间中移动时用跟随，主体静止或只在中央小范围活动时用静止。其他运镜要求（平移、变焦、推拉、移动轨道、俯仰、摇臂、升降、环绕、旋转）转换为两者中更接近的一种：“推近跑者”转为跟随，“环绕静止的雕像”转为静止。静止镜头绝不能重新构图、变宽或变窄。输入要求的视角、镜头类型和速度描述（低角度、鸟瞰、FPV、微距、鱼眼、慢动作、延时）可以保留。其他地方不要再写“跟随镜头”“静止镜头”或“镜头跟着……”；标准句中也不要在“镜头”和“跟随”之间插入“持续”等词（英文不要在 "camera" 和 "tracks" 之间加副词），否则校验脚本识别不到。
2. **主体居中。** 明确的主体（或当前活跃的主体群加核心动作物体）全程处于或接近画面中心，跟随镜头要持续让它回到中央。特写只用于静止或小范围运动的主体，会移动位置的主体用中景或全景。没有明确主体时用均衡的静止宽景（`镜头保持静止。`）。绝不虚构主体，尤其不能为了使用跟随镜头而虚构。
3. **动作开放可持续。** 描述持续、循环或有边界的运动，保证继续生成时场景依然连贯。禁用结束性措辞：最后、最终、终于、至此结束、告一段落；英文 finally, eventually, in the end, at last, concluding, concludes, to conclude, in conclusion, the end of [the interaction/scene/moment], wraps up, comes to an end/close, settles into its final state。开头的动作序列（起初 / 随后 / 接着 / 当……时）写完后，改用“整个过程中 / 与此同时 / 始终 / 随着这一过程继续”。
4. **默认自然速度。** 除非输入指定了速度，运动都按真实世界的速度来写。不要堆叠强化词（飞速地、疯狂地、无休止地、爆发式地、快成残影），表达持续用“平稳、持续、有节奏、连续不断”。人群和重复的小元素要笼统概括，不要逐个描写各自的动作。镜头静止且没有其他运动时，主体也必须有可见的动作（呼吸、眨眼、轻摆、比划）。
5. **严格忠于输入。** 保留每个实体、属性、确切数量、事件顺序、指定风格和画面文字。绝不虚构主角或主要物体，绝不丢掉被点名的实体或群体；多个群体用聚合方式呈现（“一群香料商贩”）。对已有实体补充合理的描述性细节是允许的。
6. **风格默认电影级写实**，奇幻主体也一样，除非输入明确点名或暗示了其他风格。风格标签只出现一次，放在最末尾，要简短（中文约 5–15 字，英文 3–10 词；写实默认：中文 `电影级写实摄影风格。`，英文 `Cinematic photography realistic style.`）。
7. **语言。** 输入是中文或英文时，输出同语言；其他语言输出英文。画面中要渲染的文字保持输入语言。知名作品中原名为英文的角色，使用官方英文名，不用本地译名。
8. **格式。** 只输出 prompt 本身：一整段，不换行，不用 Markdown，不加标签，不自我指涉（“这个视频展示”）。长度：英文 150–300 个词；中文 150–350 个汉字，不计标点。篇幅大致分配为主体 45%、背景 25%、镜头/光线/构图/风格/氛围 30%。只有目标模型的训练 caption 长度分布不同时才调整这个区间。

## Prompt 结构（全部写在同一段内）

1. 概要句：点出所有主要主体和场景。
2. 主体外貌：年龄、族裔、发型、服装、颜色、质感、辨识特征。
3. 用现在时描述动作：起初 → 随后 → 接着，然后写持续状态（整个过程中 / 与此同时）。
4. 环境、背景与次要元素；每种声音都要有可见声源。
5. 再次锚定主体不变的特征。
6. 技术部分：标准镜头句、景别与角度、光线、色彩、构图、氛围。
7. 风格标签放在最后。

## 多事件规则（批量与逐事件流式）

- **整个故事只用一套镜头设置。** 镜头行为（静止或跟随）、视点、角度和景别在事件 1 确定后一直复用，只有后续原始事件明确需要时才在静止和跟随之间切换。静止镜头保持原有画幅不变，新主体要进入既定画幅。跟随镜头要持续让整个活跃主体群回到画面中央，不能丢掉任何一个共同主体。居中要求唯一的例外是原始输入明确写出主体离开画面的事件，且仅限离开的过程；绝不能自行编造离开。
- **身份与场景一致。** 反复出现的实体每次都用相同的核心特征重新描述；除非输入换了地点，否则场景不变。
- **禁止跨事件代词。** 每个事件的 prompt 里，实体第一次出现时都要用已确立的完整名词短语。例如“它游向潜水员”要写成“那条背鳍带缺口的大型灰礁鲨游向潜水员……”。在同一事件内完整名词短语出现过之后，再用代词没问题。
- **叙事连贯。** 每个事件从上一个事件结束的状态接续，不能重置、瞬移，也不能改变时间、天气或持续状态。
- **每个事件使用完整长度。** 长度区间分别适用于每个事件，要警惕后面的事件越写越短。
- **仅限逐事件流式模式。** 绝不改写或重复历史事件，只输出新事件的 prompt。

## 图生视频（视频从一张输入图片开始）

输入图片就是视频的第一帧，主体、外貌、场景、光线和构图都由它定下来；prompt 写的是这一帧，以及它接下来怎么动。

- **先写图里有什么，再写怎么动。** 概要句、主体外貌和环境写的都是图片里的内容；动作从图中的姿态和情境出发，写成可以一直持续下去的运动。
- **不与图片矛盾，也不往图里加东西。** 不添加图片里没有的主体、物体或场景，也不改动服装、颜色、时间、天气或地点。用户的文字和图片对画面内容说法不一时，以图片为准。文字明确要求、图里却没有的主体，要在动作过程中走进既定画幅，不能一开头就出现在画面里。
- **景别、光线和风格跟着图片走。** 技术部分的景别、角度和光线与图片一致；风格标签写图片本身的画风（水彩仍是水彩），不套用默认的写实风格。
- **看得到图和看不到图。** 能看到图片时，照着图亲眼描述。看不到时，只依据用户对图片的说明，不要自己编造视觉细节（服装、颜色、背景、光线）；篇幅花在动作和用户确实提到的内容上。
- **镜头规则不变：** 静止或跟随，只写一句标准镜头句，图片里的主体保持在画面中央。
- **多事件：** 图片是事件 1 的第一帧，后续事件按多事件规则从它接续。

## 工作流程

```
- [ ] 1. 确定模式和输出语言；多事件时记下已确立的镜头设置和实体描述
- [ ] 2. 提取主体、确切数量、动作、场景、指定的风格/视角/速度、画面文字；有输入图片时，还要看清图里有什么
- [ ] 3. 确定镜头：根据主体运动选择静止或跟随，再定视点、角度和景别
- [ ] 4. 选择风格（默认电影级写实）和光线
- [ ] 5. 按 prompt 结构起草
- [ ] 6. 校验、修正、重新生成，直到通过（最多 3 次）
- [ ] 7. 只输出最终 prompt
```

## 校验与重试

有 shell 可用时，对草稿运行校验脚本：

```bash
python scripts/validate_prompt.py prompt.txt --lang zh       # 单事件或逐事件流式输出
python scripts/validate_prompt.py response.txt --batch 3 --lang zh   # 批量输出，期望 3 个事件
echo "<prompt>" | python scripts/validate_prompt.py - --lang zh
```

退出码为 0 表示通过。检查项包括：非空、长度区间、单一段落、没有包裹符号或标签、没有结束性措辞、没有自我指涉、除静止和跟随外没有其他镜头轨迹且静止镜头不重新构图（描述主体的运动词不算运镜，例如“镜头跟随旋转的舞者移动”里的“旋转”）、恰好一句镜头描述（不混用静止和跟随）、跟随镜头明确写出主体居中（文中描述主体离开画面时除外），以及（批量模式下）恰好 N 条。可选参数：`--lang {en,zh}`、`--no-length`、`--min-words/--max-words/--min-chars-zh/--max-chars-zh`、`--json`。

没有 shell 时，按同样的检查项人工核对。无论哪种方式，都要额外检查脚本覆盖不到的内容：忠于输入（没有虚构或丢失实体、数量准确）、静止还是跟随与主体运动相符、镜头句中点出了主体名称、主体特征的再次锚定、风格标签位于末尾、速度自然、静止镜头下主体有可见动作、跨事件一致性与代词问题，以及图生视频时与输入图片是否一致。

未通过时，把下面的反馈块追加到请求末尾，重新生成完整 prompt：

```text
上一次生成的校验反馈：
- <违例 1>
- <违例 2>
请重新生成完整输出，并修正以上所有问题。
```

最多尝试 3 次。仍不通过时要报告失败，而不是返回一条违反规则的 prompt。

## 搭建 LLM 流水线

- **System prompt：** 从 `system_prompt_CN.md` 取 `BASE`，再加 `MODE: SINGLE`、`MODE: BATCH`、`MODE: SEQUENTIAL` 三者之一。如果 API 没有 system 角色，就把它拼在 user message 前面。
- **User message：** 单事件模式直接发送原始句子。批量模式每个事件一行，写成 `事件 1：...`。逐事件流式模式使用以下模板：

```text
已定稿的历史事件（只读上下文——不要改写或重复）：
事件 1（已改写并定稿）：<改写后的 prompt 1>
事件 2（已改写并定稿）：<改写后的 prompt 2>

待改写的新事件：
<原始新事件>

请仅将上面的新事件改写为一条完整的 prompt，遵循多事件流式模式的规则。
```

  第一个事件时，把历史部分替换为 `已定稿的历史事件：无——这是序列中的第一个事件。`
- **图生视频：** 相关规则已经写在 `BASE` 里。模型能接收图片时，把图片附在 user message 里；不能时，把用户对图片的说明和原始句子一起发过去。
- **逐事件循环：** 改写第 k 个事件时，用事件 1 到 k-1 已通过校验的改写结果作为历史，改写完把结果追加到历史中，绝不传入未来的原始事件。
- **断点续跑：** 重新校验已缓存的结果，只重新生成未通过的部分。
- **Python 辅助函数**（在 `scripts/` 目录下运行，或把它加入 `sys.path`）：

```python
from validate_prompt import (
    build_system_prompt, build_streaming_user_message, build_batch_user_message,
    rewrite_with_validation,
)

system = build_system_prompt("sequential", lang="zh")
history = []
for event in events:
    prompt = rewrite_with_validation(
        call_llm, system, build_streaming_user_message(history, event, lang="zh"), lang="zh"
    )
    if prompt is None:
        raise RuntimeError(f"改写未通过校验：{event}")
    history.append(prompt)
```

  `call_llm(system_prompt, user_message) -> str` 封装你所用的任意模型或 API。批量模式传入 `expected_count=N`，返回 prompt 列表。

## 写成 MovieRoll 的 prompt CSV

`movieroll.generate` 每行读一个样本：`index`、整数 `seed`，再加 `prompt` 一列（单事件），或者 `event_1`、`event_2`……按顺序放批量或逐事件改写得到的 N 条 prompt（参见 [`example/multi_event_base.csv`](../../example/multi_event_base.csv)）。视频在各事件之间平均切分，没有时间戳列。可选列：`global_content_prompt` 和 `global_quality_prompt` 只有两列都存在时才生效，按 `global_content 事件 global_quality` 拼在每个事件前后；改写后的 prompt 本身已经完整，这两列可以不写。`input_image` 是相对 CSV 所在目录的图片路径，留空表示文生视频；同一次运行要么全是图生视频，要么全是文生视频。prompt 里有逗号，请用 CSV 库写文件。
